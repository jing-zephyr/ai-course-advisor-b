# 系统架构说明

## 总体架构

「AI课程顾问」采用**前后端分离 + 轻量 RAG + 四角色鉴权**的三层架构：

```
浏览器（四入口登录门禁 → 角色化响应式单页 index.html → 管理员观测抽屉）
        │  POST /api/login {role, password}        → 按角色签发 HMAC 时效令牌
        │  POST /api/chat {message, history, sessionId}（admin 角色响应附检索 trace）
        │  GET  /api/history?sessionId=xxx
        │  GET  /api/admin?action=stats|sessions|logs|knowledge（仅 admin 令牌）
        ▼
API 层（本地 server.js / Vercel api/ / Netlify 单函数 api.js，同一套 handler）
        ▼
业务编排 lib/handler.js ──► 检索 lib/retrieval.js ──► 知识库 data/knowledge.json
        │                        提示词 lib/prompt.js（动态注入）
        ├─ 鉴权 lib/auth.js（HMAC-SHA256 令牌签发/校验）
        ▼
LLM（DeepSeek，OpenAI 兼容协议）   会话与日志 lib/store.js → 内存层 + sessions.json/logs.json
```

## 前后端架构

- **前端**：零依赖单页应用。首屏为**四入口登录门禁**——「用户入口（学生/家长）」「教师入口」「企业/机构入口」免密自选身份，「技术人员/管理入口」口令校验；入口风格按角色分化（用户入口米色暖调 + 红/绿/黄点缀的活泼风，其余入口淡蓝理性专业风）。进入后是对话界面（左右气泡、打字动画、快捷 chips、按角色渲染的话题卡），整页主题随角色切换（`body.r-{role}`）；admin 角色解锁右上角「技术观测」抽屉，含检索追踪 / 会话日志 / 知识库状态三页签。移动端以 `100dvh` + 输入框 16px 字号适配软键盘，窄屏下四入口卡自动单列、观测面板收窄至 92vw，会话列表存 localStorage 并同步 `sessionId` 给后端，令牌存 localStorage（7 天客户端过期兜底）。
- **后端**：同一份 `lib/handler.js` 业务核心，被三种运行时复用——本地 `server.js`（原生 http）、Vercel Serverless（`api/*.js`）、Netlify Functions（`netlify/functions/api.js` 统一入口），保证本地与公网行为完全一致。API 统一 JSON 返回：成功 `{code:0, message:'ok', data:{...}}`，失败 `{code:HTTP状态码, message:'...'}`。

## 鉴权设计（演示级）

- 四入口四角色：`user`（用户·学生/家长）、`teacher`（教师）、`biz`（企业/机构）免密自选身份——身份仅用于界面主题与提示词语气差异化，不含权限差异；`admin`（技术人员/管理）口令校验，独享观测面板与检索 trace。
- 令牌：`aca.{role}.{exp}.{hmac}` 结构，HMAC-SHA256 签名（密钥仅服务端环境变量 `AUTH_SECRET`），7 天过期（覆盖评审周期，评审与工作人员一次登录即可）；签发与校验均采用**恒时比较**（`crypto.timingSafeEqual` + 长度前置校验），防时序侧信道；篡改签名或过期一律拒绝；角色字段纳入签名载荷，伪造角色必然签名不符。
- 分级返回：同一 `/api/chat` 接口，admin 角色响应额外携带检索 `trace`；`/api/admin` 四个只读动作无 admin 令牌一律 401（user/teacher/biz 令牌同样越权被拒）。
- 边界声明：该鉴权面向演示与评审场景，生产化应替换为正式账号体系（OAuth/短信验证 + 服务端会话表）。

## 数据库选型

按测试单允许范围选用**本地 JSON 文件 + 进程内内存层**（`lib/store.js`）：会话以 `sessionId` 为键存储消息数组，单会话上限 100 条、全局上限 200 会话（FIFO 淘汰）；请求日志为 200 条环形缓冲（检索追踪页签数据源）。内存层保证同实例读写一致，文件落盘为持久化兜底；本地写入 `data/*.json`，Serverless 只读文件系统下自动降级至 tmpdir。该选型零外部依赖、评审 15 分钟内可跑通；如需横向扩展，可在 `store.js` 单点替换为 SQLite/MongoDB/Redis。

## RAG 链路设计

1. **知识库构建**：三份课程素材人工切分为 36 个知识块，每块含 `id / zone（camp/teacher/platform）/ doc / chapter / title / keywords[] / content`，来源标签随块携带，保证溯源到「文档·章节」。
2. **区路由**：用三组路由词命中数判定问题所属分区；唯一胜出则限定该区检索（避免「夏令营费用」错配教师培训价格），跨区提问（如课程对比）自动回落全库。
3. **检索排序**：中文二元组切词 → 标题命中 +3 / 关键词命中 +2 / 正文命中 +1；叠加**IDF-lite 降权**（在本区出现过半的公共词如「教师」「培训」权重降至 0.2），确保「L1 学什么」精准命中 L1 专属块而非公共概述块；关键词完整命中原句再加权。
4. **Prompt 注入**：Top5 知识块连同「知识边界（只依据摘录、禁编造、标来源）」规则组装 System Prompt；另按用户身份（家长/初中/高中/教师/企业）**动态追加差异化应答策略**。temperature=0.3 抑制发挥。
5. **上下文策略**：多轮历史取最近 8 条；短句追问（<12字且路由不明）自动拼接上一条用户问题再检索，解决指代消解。
6. **过程可观测**：每次检索产出 `trace`（路由分区、区池大小、实际检索词、Top5 命中块及得分），随请求日志（分区/耗时/成功与否）写入环形缓冲，构成技术观测面板的数据源。

## 公网部署

- **生产环境**：Netlify（https://ai-course-advisor-b445432.netlify.app），纯 API digest 部署（`test/deploy_netlify.py`）：静态页 + `_redirects`（`/api/* → /.netlify/functions/api/:splat`）+ 单函数打包上传，环境变量经平台注入，与本地共用同一 `lib/` 业务核心。
- **单函数入口的由来（关键演进）**：初版将 chat/history/login/admin 拆为 4 个 Function，公网实测发现各函数运行于相互隔离的 Lambda 容器，内存与 /tmp 互不共享——chat 写入的会话在 history 中读取不到（测试用例 F5/F6 失败）。遂收敛为**单函数统一入口**（原 4 个文件保留为兼容转发并注明原因），同实例内共享内存层与临时目录，修复后公网 31/31 全量通过。
- **已知边界（如实说明）**：单函数多实例（冷启动扩容）间会话存储不共享，公网环境会话历史为实例内临时存储，长时间不活跃后可能清空；本地一键模式（server.js）为完整持久化。生产化时可在 `store.js` 单点替换为外部存储（Redis/KV/SQLite 云）。

## 安全与合规

- 密钥仅存 `.env`（已 gitignore），仓库只发 `.env.example` 模板；Serverless 端经平台环境变量注入；`ADMIN_PASSWORD` 未配置时技术入口明确返回 503 未启用。
- 输入校验：空输入、超长（>500 字）统一 400；特殊字符/注入串原样视为文本，不进入任何执行路径；前端输出经 HTML 转义。
- 接口保护：管理接口仅只读统计，不暴露消息正文编辑能力；无令牌/越权角色一律 401。
- 知识库外问题强制拒答话术，模型无资料时明确「超出现有资料范围」，杜绝编造。
